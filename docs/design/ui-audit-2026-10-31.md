# UI audit, 2026-10-31

**Status:** suggestions 1–15 were implemented on 2026-10-31. Two changes went beyond the text below:
- #1 also covers `ReportIssueSheet`.
- In #9, the fact text uses a blur-replace rather than a push, because two facts of different heights sliding past each other overlapped.

The cross-cutting additions and the UX findings are still open.

Run with the iOS Design Agent Skill (`.claude/skills/ios-design-agent-skill/`) against the working tree on 2026-10-31 (milestone 5, uncommitted).

**How it was run.** The app was built for the iPhone 18 Pro simulator, with the location set to St Paul's, and used as a guest in light and dark mode. The screenshots are in [`screenshots-2026-10-31/`](screenshots-2026-10-31/) and are cited below by number, e.g. (02). Anything that needs an account was reviewed from code only: the arrived screen, check-in celebration, signed-in profile, lists and Save to List.

**Ground rules for this app:**
- **Theme.swift is the design system.** The skill prefers system semantic colours. This app keeps the Expo palette (cream `#F5F2ED`, navy `#0A0E14`, gold) on purpose, so wherever the skill says "use `Color(.secondarySystemBackground)`", read `Theme.surface`.
- **iPhone only** (`TARGETED_DEVICE_FAMILY = 1`), so the skill's iPad reading-width checks are skipped.
- **Deployment target is iOS 26.6.** Every API suggested here exists from iOS 17.
- **System fonts only, as the skill requires.** The SF design axes are enough.

## Overall Assessment

### Strengths
- **The compass hunt has a real identity (07, 08).** It has a Canvas dial with a red north and a light-weight distance with tracked "METRES". The coordinates use monospaced digits, and gold pulse rings speed up as you close in, with a Reduce Motion fallback. This is the app's most memorable screen, and the rest of the app should build on it.
- **The marker system carries meaning.** Its five states (ambient, selected, target, visited, dimmed) each differ in size, stroke and glow, so a glance at the map says what you've visited and what you're hunting.
- **The colours are a genuine system.** Warm cream, navy and gold live in the asset catalog with light and dark pairs. The sign-in hero fades its photo into the cream background (01), which is the best single piece of atmosphere in the app.
- **The feedback basics are already done.** There are success haptics on arrival, check-in and save. Votes bounce and Save swaps its symbol. Narration times, coordinates and stop numbers use `.monospacedDigit()`.
- **Every empty and failed state is handled**, with `ContentUnavailableView` or a retry banner.

### Areas for Growth
- **Half the app leaves the theme.** Tours, My Lists and Profile sit on the system's grouped grey in light mode and pure black in dark (10, 13, 14, 17, 18), and the hunt is pure black too. Only sign-in, Explore and place detail look like Curious Places.
- **The typography has a single voice.** The stories are the product, yet they're set in the same default SF body text as the settings labels (05, 06). The Expo `design_guidelines.md` specified serif for story content, and it never shipped.
- **The category colours fail contrast, and colours mean too many things.** The Landmark pill is close to unreadable in dark mode (15, 16). Green means "open space", "checked in", "thumbs up" and "first tour stop". Gold means accent, visited, featured, target and selection.
- **Nothing on the map recedes (02).** About 150 equally weighted discs sit on a full-colour base map.
- **The rewarding moments are static.** The arrival screen and check-in celebration appear with no motion beyond one symbol swap.

## High-Priority Suggestions (implement first)

### 1. Tours, Lists, Profile and Hunt: use the brand background everywhere
**Screen:** `TourListView.swift`, `MyListsView.swift`, `ListDetailView.swift`, `SaveToListSheet.swift`, `ProfileView.swift`, `VisitedPlacesView.swift`, `ToursView.swift`, `HuntView.swift`, `CompassView.swift`

**Problem:** `List` and `Form` draw the system grouped background: cool grey in light mode (10), pure black in dark (17, 18). My Lists is plain white, with the picker on a grey `.bar` band (13). The hunt uses `Color.black` and `Color(white: 0.12)` (08), which are neutral greys, not the navy every other dark screen uses. Going from Explore (cream) to Tours (grey) feels like leaving the app.

**Suggestions:** Apply this to every `List` and `Form`:
```swift
List { … }
    .scrollContentBackground(.hidden)
    .background(Theme.backgroundRoot)
```
and give the rows the card surface. On a `ForEach`, the modifier applies to each row it makes:
```swift
ForEach(…) { … }
    .listRowBackground(Theme.surface)
```
In `ToursView`, change the picker's `.background(.bar, ignoresSafeAreaEdges: [])` to `.background(Theme.backgroundRoot, ignoresSafeAreaEdges: [])`.

The hunt forces dark mode, so the theme colours resolve to navy there:
```swift
// HuntView.body
.background(Theme.backgroundRoot.ignoresSafeArea())

// HuntPalette
static let surface = Theme.surface   // #151A23 in dark, instead of a neutral grey
```
**Why:** One background makes one world. The skill's red flag is "same background on every screen"; here the problem is the opposite, with the brand background missing from half the screens.

### 2. Place detail: set the stories in serif
**Screen:** `PlaceDetailView.swift`, `FactCard.swift`, `TourDetailView.swift`, `PlacePanel.swift`

**Problem:** The detail page is mostly long-form history (05, 06): Crippen, Marconi, Wesley. It's set in the same `.body` SF as "Descriptions" in Profile. The Expo design guidelines asked for "Georgia or Iowan Old Style (serif for historical feel)" for story content. This change restores that intent.

**Suggestions:** Use the serif axis for story text and place names only, and keep controls, badges and metadata in SF. In `PlaceDetailView`:
```swift
Text(place.name)
    .font(.title.weight(.bold))
    .fontDesign(.serif)

OverviewText(place: place)
    .font(.body)
    .fontDesign(.serif)
    .foregroundStyle(Theme.textPrimary)
    .lineSpacing(6)          // was 4; the guidelines asked for about 1.6 line height
```
Apply the same `.fontDesign(.serif)` to the fact text in `FactCard.factView`, to the tour description and title in `TourDetailView`, and to the place name in `PlacePanel` (`.title3.weight(.semibold)`). Arabic and other non-Latin translations fall back to their script's system font, so `OverviewText`'s right-to-left handling is unaffected.

**Why:** The skill's first lever is typographic contrast. Serif tells the reader "this is a story", and SF tells them "this is a control".

### 3. Category colours: light and dark pairs that pass contrast
**Screen:** `Theme.swift` (`PlaceCategory.color`), `PlaceMarker.swift`, `Assets.xcassets`

**Problem:** The category colours are fixed values used in both modes, so each mode has a category that fails. `CategoryBadge` draws caption text in the category colour on a 15% tint of itself:

| Category | Today | Light badge | Dark badge |
|---|---|---|---|
| Open space | `#4CAF50` | **2.42 : 1** | 5.01 |
| Landmark | `#6D4C8E` | 5.46 | **2.29 : 1** (15, 16) |
| Built | `#546E7A` | 4.42 | **2.80 : 1** |
| Place (bronze) | `#8B7355` | **3.75 : 1** | n/a |

The white glyph on a green marker is 2.78 : 1. The dimmed hunt markers draw a `Color(white: 0.47)` glyph on `#3A3D44` at 50% opacity, which measures 2.46 : 1 before the fade. That's why other places appear as grey blobs in (09).

**Suggestions:** Add four colour sets with light and dark variants. These values were checked against the badge tint on white, cream and dark surface:

| Asset | Light | Dark | Light badge | Dark badge |
|---|---|---|---|---|
| `CategoryOpen` | `#1B5E20` | `#81C784` | 6.21 | 6.46 |
| `CategoryLandmark` | `#6D4C8E` | `#B39DDB` | 5.46 | 5.57 |
| `CategoryBuilt` | `#455A64` | `#90A4AE` | 5.78 | 5.23 |
| `CategoryOther` | `#6B5640` | `#C4A882` | 5.57 | 5.90 |

```swift
// Theme.swift
var color: Color {
    switch self {
    case .open: Color("CategoryOpen")
    case .landmark: Color("CategoryLandmark")
    case .built: Color("CategoryBuilt")
    case .other: Color("CategoryOther")
    }
}
```
With lighter discs in dark mode, a white glyph no longer works. Use the background colour, as `HuntButton` already does on gold. That gives 5–7 : 1 in light and 7.5–9.6 : 1 in dark:
```swift
// PlaceMarker.foreground
case .ambient, .selected, .target: Theme.backgroundRoot
case .dimmed: .white.opacity(0.75)
```
**Why:** The skill requires "every colour suggestion must maintain contrast ratios". This is a deliberate departure from the Expo values in `theme.ts`, so note it in CLAUDE.md if you take it.

### 4. Explore map: let the base map recede
**Screen:** `ExploreView.swift`. The same applies to the maps in `PlaceDetailView`, `TourDetailView` (`TourRouteMap`) and `HuntMapView`.

**Problem:** At the opening zoom (02), saturated purple, green and slate discs sit on a full-colour MapKit base with green parks, yellow roads and blue water. Markers and map compete, so nothing recedes. The Expo app solved this with custom light and dark Google Maps styles. CLAUDE.md notes that "map styling will need rethinking".

**Suggestions:** Use MapKit's muted emphasis, which is the closest built-in equivalent:
```swift
.mapStyle(.standard(elevation: .flat, emphasis: .muted, pointsOfInterest: .excludingAll))
```
**Why:** Atmospheric depth means layers: a quiet background, then markers, then the panel. Combined with #3, the category discs become the brightest thing on screen. Clustering, which the Expo guidelines also asked for, is the bigger fix for density but is out of scope here.

## Medium-Priority Suggestions (second pass)

### 5. Compass: make the distance scale with Dynamic Type and roll its digits
**Screen:** `CompassView.swift` (`CompassDial`)

**Problem:** `.font(.system(size: 56, weight: .light))` is readable text at a fixed size, which breaks the skill's Dynamic Type rule. When the distance changes, the number just jumps (08).

**Suggestions:**
```swift
@ScaledMetric(relativeTo: .largeTitle) private var distanceSize = 56.0

Text(distance.map { "\(Int($0.rounded()))" } ?? "---")
    .font(.system(size: distanceSize, weight: .light))
    .contentTransition(.numericText(value: distance ?? 0))
```
The existing `.minimumScaleFactor(0.5)` keeps it inside the dial.

### 6. Arrival and check-in: give the payoff some motion
**Screen:** `HuntView.swift` (`arrived`), `CheckinSuccessView.swift`

**Problems:**
- On the arrival screen, the icon is gold but "You Arrived!" is green before check-in, so the screen mixes two success colours.
- The celebration sheet appears fully formed.
- The celebration's gradient (`#0D0B18` → `#13102A`) is a violet third palette that exists nowhere else.

**Suggestions:**
```swift
// HuntView.arrived
Image(systemName: isCheckedIn ? "checkmark.circle.fill" : "mappin.circle.fill")
    .symbolEffect(.bounce, value: isCheckedIn)
Text(isCheckedIn ? "Checked In!" : "You Arrived!")
    .font(.largeTitle.bold())
    .fontDesign(.serif)
    .foregroundStyle(isCheckedIn ? HuntPalette.green : Theme.gold)
```
In `CheckinSuccessView`, reveal the rows in sequence, with a fallback for Reduce Motion:
```swift
@Environment(\.accessibilityReduceMotion) private var reduceMotion
@State private var revealed = false

// on each row
.opacity(revealed ? 1 : 0)
.offset(y: revealed || reduceMotion ? 0 : 12)
.animation(reduceMotion ? nil : .snappy.delay(Double(index) * 0.12), value: revealed)

// on the root
.onAppear { revealed = true }
```
For the background, use navy and the dark surface with a gold wash: `[Theme.backgroundRoot, Theme.surface]`, plus a `RadialGradient(colors: [Theme.gold.opacity(0.18), .clear], center: .top, startRadius: 0, endRadius: 320)`.

### 7. Profile: show progress as a header, not as settings rows
**Screen:** `ProfileView.swift` (reviewed from code; the guest state is in 14 and 18)

**Problem:** "Places Visited 12" and "Badges Earned 3 of 9" are `LabeledContent` rows, laid out like Settings → General. They're the user's achievements, but they get the same weight as the appearance picker.

**Suggestions:** Put a stats row in the header section, with rounded numerals:
```swift
HStack {
    stat("\(checkins.checkins.count)", "Places visited")
    Divider().frame(height: 36)
    stat("\(checkins.earned.count)/\(checkins.badges.count)", "Badges")
}

private func stat(_ value: String, _ label: String) -> some View {
    VStack(spacing: 2) {
        Text(value)
            .font(.title.bold())
            .fontDesign(.rounded)
            .monospacedDigit()
            .contentTransition(.numericText())
            .foregroundStyle(Theme.gold)
        Text(label)
            .font(.caption)
            .foregroundStyle(Theme.textSecondary)
    }
    .frame(maxWidth: .infinity)
}
```
Keep "Places Visited" as a `NavigationLink` row underneath. For guests (14), make "Sign In or Create Account" a `.borderedProminent` gold button rather than a link-coloured row.

### 8. Tours list: give tours their own faces
**Screen:** `TourListView.swift` (`TourRow`)

**Problem:** Every tour row has the same gold map tile (10), so "Jack the Ripper's Footsteps" and "Crowley's Magick London" look identical apart from their names.

**Suggestions:** Put the stop count in the tile, using the rounded axis, and set tour names in the story serif:
```swift
VStack(spacing: 0) {
    Text(stopCount.map(String.init) ?? "–")
        .font(.title3.bold())
        .fontDesign(.rounded)
        .monospacedDigit()
    Text("stops").font(.caption2)
}
.foregroundStyle(Theme.gold)
.frame(width: 48, height: 48)
.background(Theme.gold.opacity(isFeatured ? 0.2 : 0.12), in: .rect(cornerRadius: 12))

Text(tour.name)
    .font(.headline)
    .fontDesign(.serif)
```

### 9. "Did you know?": make each new fact feel dealt
**Screen:** `FactCard.swift`

**Problem:** A new fact only cross-fades in. The fact card and the narration card share the same surface, border and radius, so the two cards look interchangeable (06, 16b).

**Suggestions:**
```swift
Label("Did you know?", systemImage: "bolt.fill")
    .symbolEffect(.bounce, value: current?.id)

// on the card
.sensoryFeedback(.selection, trigger: current?.id)
.transition(reduceMotion ? .opacity : .push(from: .trailing))
.background(Theme.gold.opacity(0.06), in: .rect(cornerRadius: 18))   // instead of Theme.surface
```

### 10. Sign-in: match the story voice, and stop the Google button looking disabled
**Screen:** `SignInView.swift` (01)

**Problem:** The headline is SF Bold. "Continue with Google" is a `.bordered` button tinted `textPrimary`, which shows as a flat grey capsule that reads as disabled.

**Suggestions:** Set the hero text in serif (`.fontDesign(.serif)` on the "Discover / Hidden London" `Text`). Give the Google button the card surface:
```swift
.buttonStyle(.plain)
.foregroundStyle(Theme.textPrimary)
.background(Theme.surface, in: .capsule)
.overlay(Capsule().stroke(Theme.border))
```

## Cross-Cutting Design System Additions

- **Name every colour in Theme.** Some hard-coded colours duplicate or nearly duplicate each other:
  - `#4CAF50` appears three times, as `HuntPalette.green`, `VoteButtons.upColor` and `PlaceCategory.open`, with three different meanings.
  - `PlaceMarker.visitedGold` (`#D4AF37`) is not `Theme.gold` (`#D4AF7A`).
  - `CheckinSuccessView` has its own violet colours.

  Once #3 moves the categories to assets, add `Theme.success` (check-in, thumbs up, tour start) and `Theme.danger`, and route those uses through them.
- **One card modifier.** Surface, border and an 18 pt radius are repeated in `NarrationView`, `FactCard` (three times) and the sign-in fields:
  ```swift
  extension View {
      func themedCard(cornerRadius: CGFloat = 18) -> some View {
          background(Theme.surface, in: .rect(cornerRadius: cornerRadius))
              .overlay(RoundedRectangle(cornerRadius: cornerRadius).stroke(Theme.border))
      }
  }
  ```
- **A corner-radius scale.** 8, 10, 12, 14, 16, 18 and 24 are all in use. Settle on three: 12 for controls and tiles, 18 for cards, 24 for the floating panel.
- **Typography roles,** with no manager class needed:
  - **Serif** for stories, place names and tour names.
  - **Rounded** for counts and scores.
  - **SF** for controls and metadata.
  - **Monospaced digits** wherever numbers change.

## UX Findings (outside the skill's scope)

The skill covers aesthetics only. These came up while capturing the screenshots and are functional rather than visual:

- **The app mixes two systems of units.** Distances use `.measurement(usage: .road)`, which gives yards in US and UK locales ("200 yd", 03). The hunt hard-codes metres ("173 METRES", "Get within 40 m", 08). Pick one for both. The HuntMath thresholds can stay in metres internally, as CLAUDE.md requires.
- **"End Hunt" uses a back chevron** (`chevron.left`), while the top-left `chevron.down` means "put away". Two chevrons with different meanings sit on one screen (08). An `xmark` or `stop.fill` would say "end".
- **Tour map: verify the data.** The Jack the Ripper map shows 16 pins for 17 stops, with "1" appearing twice (11). Check the tour for a repeated place or two stops at the same coordinates. `ForEach(…, id: \.element.id)` behaves unpredictably with duplicate ids.
- **The detail sheet has no bar behind "Done".** The story scrolls under the floating button (05, 06), because the sheet has no title and no toolbar background. Fix it with `.toolbarBackground(Theme.backgroundRoot, for: .navigationBar)` plus `.toolbarBackgroundVisibility(.visible, for: .navigationBar)`, or an inline title.
- **"Preparing narration…" showed for 20–30 s** on both places tested. That's the Edge Function generating audio, so it's working as designed. The copy could set expectations, e.g. "Recording narration, about 30 seconds".
- **Text selection competes with scrolling.** `.textSelection(.enabled)` on the description means a slow drag selects text and opens Copy/Translate instead of scrolling. That's a trade-off, not a bug, and worth deciding on deliberately.
- **The map is dense at the opening zoom.** About 150 overlapping markers appear (02). The Expo guidelines called for clustering.
